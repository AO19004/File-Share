# FileShare - ساخت apk روی GitHub

این پروژه برنامه اندروید FileShare است (سازگار با نسخه دسکتاپ). apk را **GitHub Actions** می‌سازد و لازم نیست Flutter، Android SDK یا JDK روی کامپیوتر شما نصب باشد.

## فایل‌ها
- `lib/main.dart`: کل برنامه
- `pubspec.yaml`: کتابخانه‌ها
- `.github/workflows/build.yml`: دستور ساخت apk (پوشه `android` و مجوزها را خودکار می‌سازد)
- `.gitignore`

## مرحله ۱: ساخت حساب و مخزن (Repository)
1. در github.com ثبت‌نام کنید (یا وارد شوید).
2. بالای صفحه روی **+** و بعد **New repository** بزنید.
3. نام را `fileshare` بگذارید. می‌توانید **Private** انتخاب کنید (فقط خودتان می‌بینید). **Create repository** را بزنید.

## مرحله ۲: آپلود فایل‌ها
در صفحه مخزن خالی روی **uploading an existing file** بزنید (یا **Add file > Upload files**).

1. این‌ها را با ماوس بکشید و رها کنید: پوشه `lib`، فایل `pubspec.yaml` و فایل `.gitignore`.
2. پایین صفحه **Commit changes** را بزنید.

سپس فایل دستور ساخت را اضافه کنید:
1. **Add file > Create new file** را بزنید.
2. در کادر نام فایل **دقیقاً** این را تایپ کنید (با اسلش‌ها، خودش پوشه می‌سازد):
```
.github/workflows/build.yml
```
3. محتوای فایل `build.yml` همین بسته را کپی و داخل کادر بزرگ paste کنید.
4. **Commit changes** را بزنید.

## مرحله ۳: ساخت apk
- بعد از آخرین commit، ساخت **خودکار شروع می‌شود**.
- بالای مخزن روی تب **Actions** بزنید. باید یک ردیف **Build Android APK** با دایره زرد (در حال اجرا) ببینید.
- بار اول حدود ۸ تا ۱۵ دقیقه طول می‌کشد.
- اگر ساخت شروع نشد: Actions > **Build Android APK** > **Run workflow**.

## مرحله ۴: دانلود apk
1. وقتی علامت **سبز ✓** آمد، روی همان ردیف کلیک کنید.
2. پایین صفحه، بخش **Artifacts** را پیدا کنید و **FileShare-apk** را دانلود کنید (فایل zip).
3. zip را باز کنید. داخلش `app-release.apk` است.
4. آن را به گوشی بفرستید و نصب کنید (اجازه «نصب از منابع ناشناس» را بدهید).

## ساخت نسخه با لینک عمومی دانلود (اختیاری)
اگر یک **tag** به نام `v1.0` بسازید (Releases > Create a new release > tag: `v1.0`)، apk در صفحه **Releases** با لینک مستقیم قرار می‌گیرد.

## اگر ساخت با ❌ قرمز تمام شد
1. روی ردیف شکست‌خورده کلیک کنید.
2. در سمت چپ، مرحله‌ای که ❌ دارد را باز کنید.
3. چند خط آخر لاگ (خط‌هایی که `error` دارند) را کپی کنید و برای من بفرستید.
4. مرحله **Analyze** خطاهای کد Dart را قبل از ساخت نشان می‌دهد و مفید است.
5. اگر خطا از نسخه Flutter بود: Actions > Run workflow و در کادر Flutter version مثلاً `3.24.5` بنویسید.

## نکته‌ها
- apk با کلید debug امضا می‌شود. برای استفاده شخصی مشکلی ندارد (برای انتشار در Google Play به کلید مخصوص نیاز است).
- بعد از نصب، برنامه «دسترسی به همه فایل‌ها» را می‌خواهد. حتماً بدهید.
- برای تغییر در برنامه، فقط `lib/main.dart` را در GitHub ویرایش کنید (آیکون مداد). با هر commit، apk جدید ساخته می‌شود.
- این کد روی دستگاه واقعی آزمایش نشده است. اگر خطای build یا رفتار عجیبی دیدید، متن خطا را بفرستید.

## اگر قبلاً فایل‌ها را آپلود کرده‌اید و می‌خواهید به‌روز کنید
1. **Add file > Upload files** را بزنید و پوشه `lib` و فایل `pubspec.yaml` جدید را بکشید و رها کنید (فایل‌های هم‌نام جایگزین می‌شوند). Commit کنید.
2. فایل `.github/workflows/build.yml` را باز کنید، آیکون مداد را بزنید، محتوا را با نسخه جدید عوض کنید و Commit کنید.
3. هر Commit یک ساخت جدید شروع می‌کند. همیشه **آخرین** اجرا را در تب Actions باز کنید (لاگ اجراهای قبلی همان خطای قدیمی را نشان می‌دهد).
4. برای اطمینان از اجرای نسخه جدید، در لیست مراحل باید مرحله **Fix plugin compileSdk + skip AAR metadata check** را ببینید.
